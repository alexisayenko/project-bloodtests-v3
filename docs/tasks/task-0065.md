# Let a newcomer hand the site to their chatbot

Retrofit: the work shipped before this file existed.

A first-time visitor faces ten sections, a JSON envelope and a
chatbot-driven import. Most already have a chatbot that can open a URL, so
the site gives them a one-line prompt to paste into it, and a page written
for that chatbot to read.

- **The card.** "New here? Ask your chatbot" (`NewcomerPromptCard.tsx`,
  prompt text in `web/src/data/sitePrompt.ts`) with "Copy prompt" and a
  "Read the guide yourself" link — always on Get Started, and on the
  Monitoring Panels grid while no report is loaded.
- **The guide.** `GET /prompt` (also `/prompt/`, `/prompt.md`), served by
  the Worker (`web/worker/siteGuide.ts`) as plain-text Markdown, public and
  cacheable, because a bot fetching the SPA would get an empty JavaScript
  shell. It covers every section with the exact button labels, and ends with
  the extraction prompt (`chatbotPrompt.ts`) verbatim; panel names and the
  schema version are read from the app's sources, not retyped.
- **Drift guard.** `web/test/site-guide.test.ts` and
  `newcomer-prompt-card.test.tsx`.

Why a Worker route rather than a static asset or an in-app page, and what it
costs: [ADR-0029](../tech/decisions/adr-0029-public-chatbot-guide-at-prompt.md).
