## Tab purposes (Results / Trends / What's in range / Charts)

**Results** — purpose: shows the actual reported values, so someone can see
exactly what was measured, when, and whether it carries a reference range or
a scheduled draw. Shown: one `ResultsTable` in a `Card` with a muted
uppercase header band — observations, then an "Indices" divider row, each
dated reading tinted by status — plus `ControlsBar` (unit system, sample
limit, and in All Observations a panel filter and marker search) and the
Scheduled block for booking a visit. Differs by view: Panel Detail renders
just that panel's own tests with the panel picker disabled; All Observations
renders every uploaded observation across panels, narrowable by panel or
search. All Observations' three tabs are also part of the URL hash (`#all`,
`#all/trends`, `#all/in-range`, pushed to history on switch); Panel Detail's
tab is local component `useState`, not URL-addressable.

**Trends** — purpose: intended to answer "how has this one marker moved over
time, and can I trust that different labs' printed values were folded into
that trajectory correctly" — per task-0027's spec, key-marker summary cards,
an interactive per-analyte timeline with a multi-lab legend and
reference-range bands, and a lab-name/unit normalization audit table. Shown:
today, nothing — `TrendsView.tsx` renders only "Nothing here yet — this tab
is a placeholder" (task-0014; full build tracked in task-0027). Differs by
view: none yet — the same empty placeholder renders identically in both
views.

**What's in range** — purpose: answers "which markers are currently outside
their reference range, and how has that shifted across past visits," all on
one shared timeline. Shown: `LabExploreView`, a normalized-overlay 2D chart
— every marker and every panel's computed indices plotted as % of its own
reference/ok-zone band on one shared axis — with a marker/index picker,
zoom, autoscale, and a "not taken" section (which also names readings
dropped because their unit couldn't be placed on the band scale);
`React.lazy` + `Suspense` since it pulls in uPlot plus the vendored
lab-explore/chart-kit engine. Differs by view: Panel Detail scopes the chart
to that one panel's markers and indices; All Observations covers every
panel's markers at once. Both share the same lazy chunk and component.

**Charts** — purpose: a second, broader visualization for spotting
correlated movement across many of a panel's markers at once, normalized
per-marker so mixed units don't distort the comparison. Shown:
`PanelChartsView`, a 3D stacked-ribbon canvas — one marker per depth plane,
each normalized to its own observed min/max, alias LOINCs merged into one
series per test — with a checkbox picker for up to 8 markers, a
translucent/opaque toggle, "Reset view," From/To year selects, and
drag-to-rotate/wheel-to-zoom; also `React.lazy` + `Suspense`, loading the 3D
engine on first visit. Differs by view: Panel-Detail-only — All Observations
has no Charts tab. That fits the mechanic: it renders one marker per depth
plane, which only stays legible over a panel's bounded, related marker set
(the picker caps at 8), not the whole database's marker list.
