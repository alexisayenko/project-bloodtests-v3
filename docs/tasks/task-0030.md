# Add a laboratory price browser screen (all labs, all tests, not scoped to a visit)

A new, separate screen where someone can browse every laboratory's full
price list for every test the app knows about — not scoped to any one
scheduled visit's chosen observations, the way pricing is shown today.

## What the code says

- **Pricing is only ever rendered through one visit's own `loincs`.**
  `PlanVisitView.tsx`'s `VisitPlanCard` calls `planRows(visit.loincs)`
  (`data/visitPlan.ts`) and `quoteSchedule(visit.loincs, lab)`
  (`data/labPricing.ts`) — both take a specific LOINC list, and the only
  caller today is a visit's own scheduled rows. There is no existing code
  path that renders `laboratories.json`'s full registry unscoped.
- **The registry itself: `web/public/data/laboratories.json` is a flat
  array of 4 laboratories** (`esculab`, `medis`, `neogenesis`, `synevo`),
  each `{id, name, locale, currency, pricesAsOf, source?, prices: PriceLine[]}`
  — `esculab` carries 46 price lines, `medis` 18, `neogenesis` 64, `synevo`
  18 (150 lines total, a line can `cover` more than one LOINC as a bundle).
  Loaded once as a static import in `data/labPricing.ts`'s
  `LABORATORIES`/`LABORATORY_BY_ID`, so a browser screen has the full
  registry available with no new loading code — just new rendering.
- **`labPricing.ts` already has the building blocks a browser would need:**
  `cheapestLineByCode(lab)` (cheapest price line per primary LOINC at one
  lab), `primaryOf(loinc)` (folds an alias to its primary code via
  `ALIAS_TO_PRIMARY`), and `formatPrice(amount, lab)` (locale-aware
  currency formatting). What's missing is anything that lists prices
  *without* a target LOINC set — e.g. "every code any lab prices, across
  all 4 labs" as a table, which none of the existing functions produce
  (`quoteSchedule` and `cheapestLineByCode` both start from a lab's own
  `prices`, not from the analyte catalog outward).
- **Nothing in the current nav or Reference Book renders lab pricing.**
  `routing.ts`'s `NAV_ITEMS` (9 entries: Get Started, Diagnostic Reports,
  All Observations, Monitoring Panels, Hormonal Pathways, Scheduled Visits,
  Medications, Reference Book, Account) has no pricing-related entry, and
  the Reference Book's `#reference/<key>` pages (LOINC database, molar
  masses, units, testosterone, FSH, HP axis) are all clinical/formula
  content — no page there touches `laboratories.json` today.

## Open questions (not decided here)

- **Where does it live in the nav?** Options: (a) a new top-level
  `NAV_ITEMS` entry (e.g. "Laboratory Prices"), sitting alongside Scheduled
  Visits; (b) a Reference Book page (`#reference/laboratory-prices`),
  consistent with how the LOINC database page already lists "every analyte
  the app knows" in one sortable table — this would be the pricing
  equivalent of that page. (b) reuses `ReferenceBookPage.tsx`'s existing
  hash-routing and table conventions; (a) gives it more prominence and
  keeps it out of the "reference/formulas" conceptual bucket Reference Book
  otherwise holds.
- **Searchable/filterable by analyte or lab?** The LOINC database page
  (`#reference/loinc-database`) is sortable by every column but panels —
  a lab-price browser has an obvious analogous need (150 price lines across
  4 labs), but whether it's a sortable flat table, one section per lab, or
  a matrix (analyte rows × lab columns, closer to `VisitPlanCard`'s own
  layout) is undecided.
- **Does it show raw price lines (including bundles) or per-analyte
  cheapest-at-each-lab, the way `VisitPlanCard` currently collapses
  bundles into "in <label>"?** A bundle line covering several LOINCs is
  real information (e.g. a lab's panel product) that a flat per-analyte
  view would obscure.
