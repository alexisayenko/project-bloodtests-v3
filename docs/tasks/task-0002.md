# Round-trip envelope metadata on import

Export wrote `generatedAt`, `subject`, `sex`, `birthYear`, `notes`
into the envelope, but import ignores all of them — re-importing an
exported file leaves the Database details form empty. Read these
fields in the v3 parse path and seed the stored envelope meta
(imported file replaces stored meta on the replace path; decide
merge-path semantics when adding a single report that carries them).

> **Note (2026-09-11):** one path does this already — Account's "Import all
> data" seeds Database details from the envelope inside the backup zip
> (`backupRestore.ts`). Import JSON and "Add" still ignore the fields.

> **Note (2026-09-20):** superseded in part by
> [ADR-0028](../tech/decisions/adr-0028-verbatim-import-export.md). Export no
> longer writes envelope metadata (`generatedAt` is removed; the stored files
> keep their own `subject`, `birthYear` and `notes`, and Database details
> keeps `sex` only), so what remains of this task is reading `sex` on every
> import path.
