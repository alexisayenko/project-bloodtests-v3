# Build the diagnostic-reports import, edit, export and LOINC workflow

The full ingestion pipeline for real lab reports, shipped across
phases 0–4:

- Chatbot prompt that turns lab PDFs/photos into v3 interchange JSON,
  hardened against real MSLab and Ygia reports (printed-LOINCs-win with
  a format gate against lab-internal codes, one draw = one report,
  pending-result skipping, bilingual one-line names, decimal commas,
  UTF-8 delivery as a downloadable file, draw-date confirmation list).
- Diagnostic Reports as the management hub: Database details
  (envelope metadata persisted to localStorage, written on export),
  guided 3-step add flow (merge), backup card (export with
  contentHash + generatedAt, import-replace, clear).
- Two-tier validation (errors block other routes; warnings don't):
  errors = missing name, missing value-and-rawValue, malformed LOINC;
  warnings = empty LOINC, missing unit, missing reference range.
- LOINC cross-check: offline catalog pass with IDF-weighted
  suggestions, per-row status dots with warning text lines, official
  names linked to loinc.org, explicit-opt-in NLM online escalation —
  the single documented exception to local-only processing.

Key decisions: FHIR naming borrowed without the spec (DiagnosticReport
/ Observation); session ids include the report's printed identifier so
same-day draws from one lab don't collide; deterministic LOINC
resolution preferred over trusting chatbot recall.
