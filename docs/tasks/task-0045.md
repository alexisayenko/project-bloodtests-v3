# Add issam.ch as a cFT reference link

Alex flagged an external page as a reliable/validated reference for
calculated free testosterone (cFT) and wants it cited somewhere in the
app's cFT-related content:

- <https://www.issam.ch/freetesto.htm> — ISSAM's (International
  Society for the Study of the Aging Male) free & bioavailable
  testosterone calculator, hosted by the Hormonology department,
  University Hospital of Ghent. Widely used/cited as a practical
  implementation of the Vermeulen equation.

(A second candidate, optimaldx.com's calculator, was dropped after
its page turned out to be login-gated with no visible methodology —
its formula/validation couldn't be confirmed, so it isn't cited.)

## What was checked

The URL was fetched (WebFetch) on 2026-09-14: confirmed it's the Ghent
Hormonology-department calculator computing free T (~2–3% of total)
and bioavailable T (free + albumin-bound), with a caveat against
relying on it when SHBG binding is disrupted (pregnancy, some hormone
treatments). The fetched page text does **not** itself name
"Vermeulen" or cite the 1999 paper — the Vermeulen attribution is
external/common knowledge, not stated on the page. Update 2026-09-16
(task-0047): the page's own script, read directly, does implement the
Vermeulen quadratic (Kt 1e9 L/mol, Ka 3.6e4 L/mol, albumin at 69 kDa),
and offers no Ly & Handelsman option. This URL is
**already** in the codebase: `web/src/data/indexDefs.ts`'s `biot`
(bioavailable testosterone) entry cites it in `references` (quote:
"bioavailable testosterone includes free plus weakly bound to
albumin", retrieved 2026-09-11) — but `cft` and `cftlh` do not cite
it.

## What the code says

`web/src/data/indexDefs.ts` defines each computed index (`cft`,
`cftlh`, `biot`, `fai`, …) as an `IndexDef` carrying a `references`
array (not `citations` — that's the field name to use), each entry
shaped `{ organization, document, year?, url, doi, retrieved?, quote }`.
`quote` is a short verbatim excerpt backing the specific claim.

Two surfaces render `def.references`, both reading the same array —
no duplication needed between them:

1. **Hormonal Pathways cFT badges** (`HormonalPathwaysView.tsx`):
   `indexReference()` maps `def.references` into a `SourcesBlock` that
   renders `organization. <linked title> (year), retrieved <date>` —
   `quote` is not shown here, only used for the source data / other
   surfaces.
2. **Reference Book's per-index page** (`ReferenceBookPage.tsx` line
   181, `def.references.map(ref => <ReferenceItem .../>)`) — renders
   the full reference including (per `ReferenceItem`, not yet
   inspected in detail) presumably the quote too.

Because both surfaces read `cft`/`cftlh`'s own `references` array,
adding an entry there is a single edit that appears in both places.

## Proposal

**Add issam.ch to `cft`'s `references` array**, the same way it's
already used on `biot` — same organization string ("ISSAM (Hormonology
department, University Hospital of Ghent)"), a `quote` scoped to what
the page actually supports (e.g. that it computes free and
bioavailable T from total T/SHBG/albumin via the standard
competitive-binding approach), not an unverifiable claim that the page
states "Vermeulen" by name.

Decide separately whether `cftlh` (Ly &
Handelsman) also gets issam.ch — the ISSAM calculator is Vermeulen-only
as far as could be confirmed, so it likely belongs on `cft` alone
unless someone verifies it also offers the Ly & Handelsman regression.
