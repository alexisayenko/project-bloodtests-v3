# Show a date's full date and lab name on results-table header click

In a Results tab's Observations table, a date column header currently shows
only a month/year label. Clicking it should open a popup with that column's
full date (`D MMM YYYY`, e.g. "14 Sep 2026") and the name of the lab that
performed that draw.

## What the code says

- Date column headers render in `TableHead` in
  `web/src/components/conditions/ResultTables.tsx` (around line 132-143): a
  plain, non-interactive `<th>{formatMonthYear(date)}</th>` per date — no
  click handler today.
- `formatMonthYear` (`web/src/data/months.ts`) gives "Sep 26"; a separate
  full-date formatter already exists, `formatFullDate` in
  `web/src/components/conditions/ui.ts` (`d.toLocaleDateString('en-US', {
  month: 'short', day: 'numeric', year: 'numeric' })`), but it renders
  "Sep 14, 2026", not the "D MMM YYYY" order this task asks for — so either a
  new formatter or a variant is needed.
- The underlying report/observation type does carry a lab name per dated
  reading: `MedicalConditionsPage.tsx`'s `buildAllResults` (around line
  152-160) builds each `ResultEntry` as `{ loinc, date: session.date, place:
  session.place, result: item }`, one `place` per report/session, reused for
  every observation in it. `Popup.tsx` already renders this pattern elsewhere
  (`{formatMonthYear(entry.date)} · {entry.place}`, line 80), and
  `ui.ts`'s `namedLab(place)` turns an empty/placeholder/"Unknown Lab" field
  into `undefined`.
- A results table's `visibleDates` are exact date strings (not month keys),
  and `resultsByDate` / `buildRowCells` (`ui.ts`, `buildRowCells` around line
  260-271) key strictly by that exact date: `buildRowCells` picks the first
  `allResults` entry matching `{date, loinc}` via `.find(...)`, and
  `MedicalConditionsPage.tsx`'s `resultsByDate` map is also keyed by exact
  date only, overwriting on collision. There is no session/report id in the
  date key.

## Open questions

- **Multiple labs on one date column.** Nothing stops two different reports
  (sessions) from sharing the same draw date — `resultsByDate` and
  `buildRowCells`'s `.find()` both key by date alone and would silently
  collapse to one entry (whichever session was built first) if that
  happened. If two same-day reports have different `place` values, what
  should the header popup show — the first, a list, or "multiple labs"? This
  needs a decision before implementation; worth checking on real data
  whether same-day multi-lab draws actually occur.
- Does this affect Indices rows too? Indices are computed per date from
  `resultsByDate`, which has no per-index place of its own (an index isn't
  drawn at one lab in the first place) — likely out of scope, but worth
  confirming the popup is offered only for the Observations block.
- Exact popup component/pattern to reuse — `Popup.tsx` already exists for
  per-observation values; worth checking whether a header-click popup should
  reuse it or needs its own smaller variant.
