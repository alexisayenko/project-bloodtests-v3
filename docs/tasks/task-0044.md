# Add FAI and reliability badges (heuristic/consensus/guideline) to Hormonal Pathways

Alex's own words: "Add FAI on hormonal pathways -- just note there its
level of reliability. In addition, mark reliability level for each
index on that page -- use our standard terms and badges (heuristic,
consensus, guideline)."

Two parts: (1) add a Free Androgen Index (FAI) badge to the Hormonal
Pathways page, with a reliability note; (2) add a reliability marker
to every index badge already on that page, using the app's existing
evidence-grading vocabulary.

## What the code says

**The vocabulary is real and structural, not just prose.** Every
`IndexDef` in `web/src/data/indexDefs.ts` carries `evidenceLevel:
string` (declared in `web/src/data/computedIndices.ts:268`), populated
with exactly `'heuristic' | 'consensus' | 'guideline'` across all
current entries. It is already rendered today as a colored pill by
`ReferenceBookPage.tsx`'s `EvidenceBadge`/`EVIDENCE_BADGE` map
(lines 67-70, 97-99: guideline = accent, consensus = soft green,
heuristic = soft amber) next to each index's Reference Book page
title. This is the "standard terms and badges" Alex means -- reuse
this palette/pill, don't invent a new one.

Side note: there's also a narrower, older `level: 'consensus' |
'heuristic'` field on the same interface (never `'guideline'` in any
entry) that looks vestigial next to `evidenceLevel` -- not this
task's job to clean up, but flagging it since it could confuse
whoever touches this next.

**FAI already exists as a full `INDEX_DEFS` entry** --
`web/src/data/indexDefs.ts:296-308`, key `'fai'`: formula (`T / SHBG
× 100`, both nmol/L), full `meaning`, `consensus` prose,
`evidenceLevel: 'heuristic'`, two citations (Vermeulen 1999's own
validation paper, which calls FAI "not a reliable index of
bioavailable T"; an LHSC lab guide), and a working `fn`. It's already
live in the Hypogonadism panel cards and the Reference Book. So this
task is not "implement FAI from scratch" -- the formula, evidence
grading and citations are already written and reviewed; the work is
wiring it into the Hormonal Pathways page's badge column, which
doesn't currently show it.

**Hormonal Pathways' badge column does not reuse `INDEX_DEFS` prose.**
`HormonalPathwaysView.tsx`'s own `BADGES: ReadonlyArray<Badge>`
(lines 861-948, 10 entries: Total T, Bio-T, measured Free T, cFT
Vermeulen, three `unavailable: true` cFT variants with no formula,
T/LH, DHT/T, T/E2) hardcodes its own `meaning`/`low`/`high`/`caveats`
strings independently of `indexDefs.ts`. A badge's `measure` key
(e.g. `'cft'`, `'biot'`, `'tlh'`) only pulls the *computed number and
status* from the Snapshot -- not the index's `meaning` or
`evidenceLevel` text. The `Badge` interface has no reliability field
today, and none is displayed anywhere on this page. Adding it is real
new scope, not just exposing a value that's already there.

Of the 10 existing badges, only some map to a real `INDEX_DEFS` entry
with an `evidenceLevel` to reuse: Bio-T (`biot`, consensus), cFT
Vermeulen (`cft`, guideline), T/LH (`tlh`, heuristic), DHT/T (`dhtt`,
guideline), T/E2 (`te2`, ?). Total Testosterone and measured Free
Testosterone are raw lab values, not computed indices -- no
`evidenceLevel` concept applies to them. The three `unavailable`
cFT variants (Ly & Handelsman, Sartorius, Zakharov) have no formula
implemented at all, so no `INDEX_DEFS` entry and no `evidenceLevel`
exists for them either.

## cFT-Z (Zakharov)

Third ask, added after the first draft of this task: write in a real
cFT (Zakharov) badge instead of leaving it permanently `unavailable`.

### Current state, exactly as coded today

`HormonalPathwaysView.tsx:920-926` — the `cft-zakharov` entry in
`BADGES`:

```ts
{
  id: 'cft-zakharov', name: 'cFT (Zakharov)', unavailable: true,
  meaning: 'Another published calculation for free testosterone — a
    multi-step, dynamic allosteric model of testosterone's binding to
    SHBG (Zakharov et al. 2015, Molecular and Cellular Endocrinology),
    distinct from the Vermeulen equation (cFT) used above.',
  low: 'Not shown — no formula is implemented.',
  high: 'Not shown — no formula is implemented.',
  caveats: 'Zakharov et al.'s (2015) full text and equations are
    published only behind Elsevier's paywall — unreadable via PMC, its
    DOI, or the authors' institutional pages — so no value can be
    computed here. Independently of that, Fiers et al. (2018) tested
    this model against direct equilibrium-dialysis measurement and
    found it ran roughly twofold high (median ratio ~2.05), despite
    Zakharov's own validation reporting good agreement — so even a
    readable copy would carry a reported accuracy problem.',
},
```

With `unavailable: true`, `Badges()` (same file, ~line 969) never
looks up a `measure`, so the collapsed face always renders `value =
'Not available'` and a neutral status dot; the expanded card shows
the `meaning`/`caveats` text above verbatim, with `low`/`high` both
"Not shown — no formula is implemented." No `INDEX_DEFS` entry exists
for Zakharov — nothing to compute from.

`indexDefs.ts:260` (in `cft`'s own `consensus` prose) and `:270`
already carry a citation for the source paper: Zakharov MN, Bhasin S,
Travison TG et al., *"A multi-step, dynamic allosteric model of
testosterone's binding to sex hormone binding globulin,"* Molecular
and Cellular Endocrinology, 2015, PMID `25240469`, DOI
`10.1016/j.mce.2014.09.001` — plus the same Fiers et al. 2018 (JCEM
103:2167) finding cited in the badge's caveat. `task-0024.md` (lines
1180-1225) documents that this exact paper was checked for a
freely-readable copy twice (2026-09-12) — no PMC full text for that
PMID, ScienceDirect resolves only to the paywalled abstract, no
institutional or author copy found either time.

### What's missing to implement it — known vs. unknown

**Known, already in the repo:** which paper (citation above, with DOI
and PMID — this is not a vague "some paywalled paper," it's this
specific one); that Fiers et al. 2018 independently re-tested it and
found it ran ~2x high against equilibrium dialysis even when correctly
implemented; that the model is "multi-step," "dynamic," "allosteric"
and, per `task-0024.md:1185`, "iterative" — i.e. not a closed-form
algebraic formula like Vermeulen's quadratic (which `cft` already
implements), but a numerical/iterative procedure.

**Unknown / not in the repo, and not something this agent should
invent:** the actual equations, step sequence, and numeric constants
of that iterative model. Nobody who worked on this repo has read the
paywalled full text, so no stub, TODO, or partial formula for it
exists anywhere in `indexDefs.ts` or `computedIndices.ts` beyond the
citation itself. The badge's caveat says "full text and equations,"
not just "coefficients" — this is a materially bigger ask than Ly &
Handelsman's or Sartorius's blockers, which are plain regression
constants; Zakharov's is a whole multi-step numerical model whose
mechanics are unknown here.

**Bottom line for Alex:** implementing this for real needs Alex (or
someone with journal access) to obtain the actual Zakharov et al. 2015
full text — via institutional access, interlibrary loan, or contacting
the authors — and pull the exact iterative equations and constants
from it. This agent has no access to that paywalled text and will not
guess at or fabricate the model. Once the real equations are in hand,
implementing them as a new `fn` in `indexDefs.ts` (mirroring how `cft`
implements Vermeulen's quadratic) is straightforward; grading it
`evidenceLevel` would then reasonably be `heuristic` given Fiers'
~2x-high finding, mirroring how `fai` is graded despite having a
citation and a working formula.

### Update, 2026-09-15 — a candidate equation source that did NOT check out

Alex found a screenshot (source unconfirmed) titled "5. The Zakharov
Allosteric Model (2015)" showing a partial cubic equation —
`Ks1 · Ks2 · [FT]^3 + (Ks1 + 2·Ks1·Ks2·[SHBG] − Ks1·Ks2·[TT]) · [FT]^2
+ (1 + Ks1·[...` — cut off mid-term, with constants Ks1 = 1.1×10^9
L/mol, Ks2 = 1.0×10^7 L/mol, and a citation reading "National
Institutes of Heal..." (truncated). Alex supplied
`https://pmc.ncbi.nlm.nih.gov/articles/PMC7983478/` believing that was
the source.

This was checked (WebFetch plus a PubMed MCP full-text pull,
cross-verified): **the equation is not in that article.** PMC7983478
is Nielsen et al., "Free testosterone and cardiometabolic parameters
in men: comparison of algorithms," *Endocrine Connections*, DOI
10.1530/EC-20-0552. It cites Zakharov's model only conceptually — an
"ensemble allostery framework," "allosterically coupled SHBG
monomers" — and treats its output (cFTZ) as a black box computed
elsewhere. No cubic equation, no Ks1/Ks2 constants, and no "Zakharov
Allosteric Model" section heading appear anywhere in it. It also
states it used "a fixed average level of albumin" for Zakharov's
algorithm in their own implementation — which conflicts with this
task's premise above that Zakharov's model doesn't need albumin at
all.

So, plainly: the partial cubic equation and constants are from an
**unverified source**, not PMC7983478 (checked, doesn't contain them);
the equation itself is **incomplete** (cut off after the `[FT]^2`
term — no `[FT]^1` or constant term visible, so it can't be solved as
given even if the source were confirmed); and the "no albumin needed"
premise now has at least one contradicting data point. What document
the screenshot actually came from is not something to speculate about
here — just recording that it's unconfirmed.

**Conclusion: Zakharov remains genuinely blocked.** Still need the
actual primary-source equation (complete, all terms) — or a verified
secondary source that fully reproduces it — before this can be
implemented.
