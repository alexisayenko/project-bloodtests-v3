# Add LP-IR as a computed index alongside the reported observation

Paneloom already stores LP-IR as a plain reported observation — LOINC
`62255-5`, in `web/public/data/analyses.json` and the Insulin Resistance
panel's `extraLoincs` in `monitoring-panels.json`, documented in
[lp-ir.md](../tech/lp-ir.md). Product decision from chat, 2026-09-18: an
inferable value belongs under Indices (`INDEX_DEFS` in
`web/src/data/indexDefs.ts` / `web/src/data/computedIndices.ts`, alongside
HOMA-IR, AIP); a lab-reported value with the same clinical meaning stays a
separate Observation; the two are never merged (printed values are never
overwritten by derived ones — [ADR-0003](../tech/decisions/adr-0003-store-only-what-the-lab-printed.md)).
LP-IR is inferable from six NMR LipoProfile particle measurements, so it gets
a computed `INDEX_DEFS` entry **alongside** the existing `62255-5`
observation, not replacing it. See also
[computed-indices.md](../tech/computed-indices.md).

This is a fully researched, decision-ready spec, not yet implemented.

## Algorithm source

Shalaurova I, Connelly MA, Garvey WT, Otvos JD. "Lipoprotein Insulin
Resistance Index: A Lipoprotein Particle–Derived Measure of Insulin
Resistance." *Metab Syndr Relat Disord.* 2014;12(8):422-9. PMID 24959989,
PMCID PMC4175429, DOI 10.1089/met.2014.0050 (open access on PMC:
https://pmc.ncbi.nlm.nih.gov/articles/PMC4175429/).

Its Table 3, reproduced verbatim below. Final score = sum of the six
subscores, range 0–100.

| <39.2→0, 39.2–41.1→1, 41.2–42.8→2, 42.8–44.3→4, 44.4–46.0→6, 46.1–48.1→9, 48.2–50.3→10, 50.4–51.6→11, 51.7–53.2→12, 53.3–55.3→15, 55.4–58.4→18, 58.5–61.0→19, 61.1–63.0→22, 63.1–64.1→25, 64.2–65.1→28, >65.1→32 | <0.7→0, 0.7–1.0→2, 1.1–1.3→5, 1.4–1.5→7, 1.6–1.7→9, 1.8–2.5→12, 2.6–3.7→15, 3.8–5.3→18, 5.4–7.9→19, >7.9→22 | <21.0→6, 21.0→5, 21.1→3, 21.2→2, >21.2→0 | <90→0, 90–104→1, 105–128→3, 129–372→4, 373–961→6, >961→8 | <8.7→20, 8.7→16, 8.8→12, 8.9→10, 9.0→9, 9.1–9.2→7, 9.3→5, 9.4–9.5→4, 9.6–9.7→2, >9.7→0 | <3.1→12, 3.1–4.0→10, 4.1–5.4→9, 5.5–6.3→8, 6.4–7.1→6, 7.2–8.0→4, 8.1–9.3→2, >9.3→0 |

The LDL-size column's exact single-value cut rows (21.0 / 21.1 / 21.2, not

## Supporting outcomes evidence (secondary — not the algorithm source)

Harada PHN et al. "Lipoprotein Insulin Resistance Score and Risk of Incident
Diabetes During Extended Follow-Up of 20 Years: The Women's Health Study."
*J Clin Lipidol.* 2017;11(5):1257-1267.e2. PMID 28733174, PMCID PMC5644504,
DOI 10.1016/j.jacl.2017.06.008. A 25,925-woman, 20.4-year cohort validation:
higher LP-IR quartiles associate with incident type 2 diabetes (Q4 vs Q1
adjusted HR 2.21, 95% CI 1.75–2.80). Already cited in
[lp-ir.md](../tech/lp-ir.md). Cites Shalaurova as the score's origin rather
than defining it itself.

## Six required inputs

Confirmed via the NLM LOINC API; none currently in the catalog.

| Input | LOINC | Long common name | Unit |
| --- | --- | --- | --- |
| VLDL size | `62254-8` | Lipoprotein.pre-beta [Entitic length] in Serum or Plasma | nm |
| Large VLDL-P | `43728-5` | Lipoprotein.pre-beta.subparticle.large [Moles/volume] in Serum or Plasma | nmol/L |
| LDL size | `17782-4` | Lipoprotein.beta.subparticle [Entitic length] in Serum or Plasma | nm |
| Small LDL-P | `43727-7` | Lipoprotein.beta.subparticle.small [Moles/volume] in Serum or Plasma | nmol/L |
| HDL size | `62253-0` | Lipoprotein.alpha [Entitic length] in Serum or Plasma | nm |
| Large HDL-P | `43729-3` | Lipoprotein.alpha.subparticle.large [Moles/volume] in Serum or Plasma | µmol/L |

## Scope / acceptance criteria

1. **Re-verify the Shalaurova table** once more against
   https://pmc.ncbi.nlm.nih.gov/articles/PMC4175429/ before encoding it as
   reference data.
2. **Catalog the six analytes** in `web/public/data/analyses.json`
   (`friendlyName`, `shortName`, `unit`, `allowedUnits` — follow existing
   entries' shape) and validate against `analytes-1.schema.json`.
3. **Encode the scoring table as reference data**, this repo's convention
   for a step-function table per
   [ADR-0010](../tech/decisions/adr-0010-analyte-catalog-is-the-source-of-truth.md)
   and
   [ADR-0020](../tech/decisions/adr-0020-constants-from-cited-data-calculators-are-cross-checks.md):
   JSON + schema + ajv test, the same pattern
   `web/public/data/martin-hopkins-ldl-table.json` uses (its schema
   `web/public/schema/martin-hopkins-ldl-table-1.schema.json`, its loader
   `web/src/data/martinHopkinsLdl.ts`, its conformance test
   `web/test/martin-hopkins-data.test.ts`) — model the new file on that
   trio, e.g. `web/public/data/lp-ir-score-table.json`.
4. **Add an `INDEX_DEFS` entry** in `indexDefs.ts` / `computedIndices.ts`
   citing both papers, reading the six inputs, and declining (rendering "–")
   when any input is missing rather than guessing.
5. **Leave `62255-5` and `lp-ir.md` untouched and unmerged** — the computed
   index is additive, not a replacement.
6. **Document a deviation note** (ADR-0020 style): commercial LP-IR reports
   carry operational "not reportable" conditions (non-fasting, hemolysis,
   specimen age, interfering substances) that a home computation can't
   detect, so the computed value must be labeled a cross-check, not a
   replacement for the lab-reported score.
7. **Tests**: golden-master cases against the reproduced table; schema/ajv
   conformance for the new reference-data file; `INDEX_DEFS` band/zone
   behavior if applicable. No reference band for LP-IR appears in either
   source above, so check first whether the index should render band-less
   (numeric-only, no status) — [computed-indices.md](../tech/computed-indices.md#bands-and-status)
   already documents this as a deliberate, existing pattern ("An index with
   neither `cut` nor `bandsBySex` is deliberately band-less and never has a
   status"), used today by several Hypogonadism testosterone-ratio indices
   in `indexDefs.ts`.
