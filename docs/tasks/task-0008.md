# Adopt UCUM for unit validation and conversion

UCUM (Unified Code for Units of Measure) is the standard unit grammar
and LOINC's official companion — the `EXAMPLE_UCUM_UNITS` field the
NLM stage already fetches is UCUM. NLM ships a JS library for it
(`ucum-lhc`: syntax validation, canonicalization, conversion).

Scope note: UCUM as the *target vocabulary* is no longer open — it was
settled on 2026-09-07 by
[ADR-0007](../tech/decisions/adr-0007-ucum-as-the-unit-vocabulary.md),
and the normalization pass that would write canonical units into `unit`
is its own task,
[task-0011](task-0011.md). What is still open here, and all this task
covers, is adopting the NLM **library** (`ucum-lhc`) for syntax
validation and derived conversion.

Today's needs are covered by the curated tables in
`web/src/data/unitNormalization.ts` (printed unit → Latin spelling →
UCUM code, plus `convertValue` and the LOINC dimension check), by
`normalizeUnit` (spelling folding: μ/µ/u/mcg) and `canonicalUnit`
(which additionally folds per-mL to per-L for comparison only) in
`loincCheck.ts`, and by the per-code allowed-unit sets
(`DEFAULT_UNITS` + `ALLOWED_UNITS`, task-0009 — now derived from the
analyte catalog by `analyteCatalog.ts`), which drive resolver variant
selection and the unit-contradiction warning. None of that rewrites
stored data. Deliberately not adopting the UCUM library yet —
it's a real dependency and parsing lift.

Adopt when either trigger fires:
- the SI/US unit toggle's conversions outgrow the curated set, or
- malformed/garbage units from chatbot-generated files become common
  enough to need real syntax validation (the deferred "plausibility
  check" on codeless rows).

When adopted: canonicalize units through UCUM instead of string
folding, validate every printed unit's syntax, and derive conversions
rather than curating them.
