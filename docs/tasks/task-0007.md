# Derive LOINC from printed name and unit, demote printed codes to evidence

Chatbots supplying LOINCs from memory hallucinated
plausible-but-wrong codes (FT3 given TSH's 3016-3, HDL given LDL's
2089-1, MCV/MCH swapped). Decision recorded in
[ADR-0004](../tech/decisions/adr-0004-derive-loinc-from-name-and-unit.md):
the app derives each code deterministically from printed name +
unit; a printed code is corroborating evidence only.

Shipped: `resolveLoinc` ladder in `loincCheck.ts` (Latin-name pass
→ `lang`-translation pass, unit-aware with SHORT_LABELS/ALSO_REFS
units hard-selecting unit variants, `confident` flag from score +
dominance + unit consistency), reworked `crossCheckLocal`
(derivation-vs-printed-code mismatch with `derived`, fallback to
the old name-overlap check), NLM stage extended with
`EXAMPLE_UCUM_UNITS` for the same unit selection, detail-view
suggestion chips with unit labels plus an "Apply suggestions"
button through the edit-draft path, and a chatbot prompt that
only ever transcribes printed codes.
