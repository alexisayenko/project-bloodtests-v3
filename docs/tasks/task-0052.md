# Add a normalize toggle to What's-in-range and hoist Unit System above the tab strip

Alex requested two changes to the Results/Trends/Charts/What's-in-range
area of Panel Detail and All Observations.

## 1. "Normalize" toggle on the What's-in-range chart

Today the chart (`LabExploreView.tsx` over the vendored
`web/src/vendor/lab-explore/` + `chart-kit/`) always plots every marker
as % of its own reference range / ok-zone band on one shared axis —
that's what makes overlaying markers of wildly different absolute
scales (e.g. HGB in g/dL next to Glucose in mmol/L) possible on one
chart.

Alex wants a toggle: **on** (default) keeps today's normalized 100%-zone
view; **off** shows actual values instead.

**Open design question, needs deciding before implementation**: the
chart normalizes precisely because markers don't share a scale.
Toggled off, what does "actual values" mean for a multi-marker
selection?
- Does the axis only allow same-scale markers to be picked together
  when un-normalized (rejecting or hiding incompatible ones)?
- Does the axis dynamically rescale per whatever's selected (fine for
  one marker, ambiguous for several different-unit ones)?
- Does un-normalized mode force single-marker selection only?
- **Logarithmic axis** (Alex's suggestion, 2026-09-15): a log-scale
  y-axis compresses the dynamic range so a low-magnitude series (e.g.
  Glucose, ~5 mmol/L) and a high-magnitude one (e.g. Hemoglobin,
  ~150 g/L) both stay visually legible on one shared axis instead of
  one flattening the other. Caveat: it doesn't reconcile different
  *units* the way % normalization does — it only keeps unrelated
  magnitudes readable together, not clinically comparable. Needs
  strictly-positive values, which lab readings always are, so no real
  downside there.
- **Per-unit left/right axis** (Alex's suggestion, 2026-09-15): uPlot
  (the engine `chart-kit` wraps) natively supports multiple y-axes, so
  a left axis for one unit and a right axis for a second is realistic
  and not exotic. Doesn't scale past two distinct units in one
  selection, though — the picker allows selecting many markers at
  once, and a third/fourth axis gets visually cluttered with no clear
  way to show which line reads off which axis. Would need a fallback
  (e.g. normalize or log-scale automatically kicks back in once 3+
  distinct units are selected) rather than trying to draw N axes.

**Hard constraint surfaced 2026-09-15**: a chart axis must always carry
a real unit label — an axis of raw numbers with no unit (units shown
only in the tooltip) is bad data-viz practice, not a stylistic
preference, and should not be reachable. This rules out "one shared
axis of raw mixed-unit numbers with no label" as an option outright
(that includes log-scale of raw values — the transform doesn't give
mixed units a legitimate single label either). It's fine wherever the
axis genuinely has one real unit: a single marker selected (its own
unit), normalized mode ("%"), or the dual left/right axis case (each
side its own unit). Raw-values mode therefore needs to either restrict
selection to one marker/same-unit group at a time, or fall back to
normalized automatically once the selection mixes units.

This touches the vendored `lab-explore`/`chart-kit` internals
(`placeOnBandScale`, the axis/scale logic), which CLAUDE.md documents
as deliberately generic-only and vendored as-is except for narrowly
scoped exceptions (e.g. the earlier MMM YY date-format change,
task-0051's lab-name/decimal-rounding change) — this is a bigger lift
than either of those, not a one-line tweak.

## 2. Hoist Unit System above the tab strip

Today `ControlsBar` (Unit System, Last N Samplings, Show observations
from, Find a marker) renders once, inside the Results tab only, per
CLAUDE.md: "no other tab shows it." Alex asked whether these should
sit above the Results | Trends | Charts | What's-in-range tab strip
instead, since some of them are meaningful across all tabs.

**Decided (2026-09-15, Alex chose A1 of a lettered/numbered menu):**
split the bar rather than move it whole — **Unit System** moves above
the tab strip (shared across every tab, since it also affects the
chart's scale/labels), while **Last N Samplings**, **Show observations
from**, and **Find a marker** stay inside the Results tab, where
they're actually meaningful (the chart already has its own panel
picker for series selection; sample-limit and marker-search don't
apply to it).

## First step, decided 2026-09-15

Alex chose to ship a simple first version rather than solve the full
multi-unit-axis question up front: a two-state toggle —

- **Normalized values** (default) — today's behavior, % of reference
  range/band on one shared axis.
- **Absolute numbers** — raw values on one shared left axis, with
  *no* unit label on the axis itself (units still shown per-point in
  the tooltip, from task-0051's lab-name/decimal work). Explicitly
  accepted as not fully solving the "axis must carry a unit" concern
  above — a deliberate first pass to see how it looks and iterate from
  there, not a final decision on the open design question.

## Implementation (2026-09-15)

First-step toggle shipped: a `SegmentedControl` ("Values: Normalized
values / Absolute numbers") above the What's-in-range chart in
`LabExploreView.tsx`, session-only `useState` (unpersisted, matching
the existing zoom/panel-picker state), threaded through
`LabExploreModel.normalized?: boolean` (default `true`) into the
vendored `lab-explore.ts`'s `#buildData()` (branches raw value vs.
%-of-band), `#makeChart()` (drops the shaded 0-100% band in absolute
mode) and `#render()` (blanks the axis caption and swaps the intro
copy in absolute mode). No change to `exploreModel.ts`'s
`buildExploreModel` — it already produces band-unit values; the toggle
only changes whether the vendored renderer additionally divides by the
band range. Verified: `tsc -b` clean, `npx vitest run` 884/885 (no
fixture changes needed), visually confirmed in both Panel Detail and
All Observations — Absolute mode shows raw per-marker values sharing
one unlabeled axis, tooltip still carries each point's real unit,
Normalized mode unchanged.

## Scope note

Part 2 (hoist Unit System above the tab strip) is not yet implemented.
The toggle above is explicitly a first pass per the "First step"
section — the open multi-unit-axis design question (log-scale,
dual-axis, or restrict-to-same-unit) is still unresolved for anything
past this simple two-state version.
