# Let clicking the Hormonal Pathways date open a dropdown of report dates (D MMM YYYY)

Hormonal Pathways' date stepper only steps one date at a time. Clicking the
date label itself should open a dropdown listing every available date so the
user can jump directly, formatted "D MMM YYYY" (e.g. "14 Sep 2026").

## What the code says

- The stepper is `DateStepper` in
  `web/src/components/conditions/HormonalPathwaysView.tsx` (around lines
  1018-1030): a `<fieldset>` with Previous/Next buttons (`‹`/`›`, each
  `disabled` at its list end, matching CLAUDE.md's description) and a plain,
  non-interactive `<span className="mc-pathway-stepper-label">` showing
  `formatMonthYear(date)` — no click handler, no dropdown today.
- Its `dates` prop is built in the enclosing `HormonalPathwaysView` component
  (around line 1052) via `panelDates(PANEL_NAME, panelTests,
  allResults).reverse()` — the same `panelDates` helper (`markers.ts`) Panel
  Detail's own date handling uses — then indexed by `date ?
  dates.indexOf(date) : -1` and changed via `setPicked(dates[i] ?? null)`
  (line 1114). A dropdown needs no new data source: `dates` already is the
  full ordered list the stepper walks.
- **No "D MMM YYYY" formatter exists yet.** `web/src/data/months.ts` only
  has month-level formatters (`formatMonthYear` → "Sep 26",
  `formatMonthFullYear` → "Sep 2026"), neither day-level.
  `web/src/components/conditions/ui.ts`'s `formatFullDate` (line 44) is the
  only day-level formatter and produces `en-US` `"short day, numeric year"`
  order — **"Sep 14, 2026"**, not "14 Sep 2026".
- task-0026 (Show a date's full date and lab name on results-table header
  click) hits the exact same gap: its "What the code says" section
  independently flags that `formatFullDate` doesn't match the "D MMM YYYY"
  order it needs either, and concludes "either a new formatter or a variant
  is needed" — task-0026 has **not** introduced one yet (it's still `to
  do`), so there is no existing `formatFullDate`-variant to reuse today.
  Whichever of task-0026 or this task lands first should add the shared
  "D MMM YYYY" formatter (likely beside `formatFullDate` in `ui.ts`, or in
  `months.ts` alongside the other date-key formatters) and the other should
  reuse it rather than writing a second one.

## The ask

Make the date label in `DateStepper` clickable, opening a dropdown/popup
listing all of `dates` formatted "D MMM YYYY", selecting one calling the
same `onChange`/`setPicked` path the arrow buttons already use. Reuse
whatever "D MMM YYYY" formatter task-0026 introduces if it lands first;
otherwise add it here and note in task-0026 that it should reuse this one.
Popup/dropdown mechanics can follow an existing in-app pattern (e.g. the
month-select dropdowns already in Scheduled Visits) rather than being
invented from scratch — worth checking `MonthSelect` (`ui.ts`/`scheduled.ts`
usage) as a precedent before building a new dropdown component.
