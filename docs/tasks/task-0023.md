# Monitoring panels controls & customization — name toggle, status filters, and edit panels mode (hide/show, custom panels, drag-and-drop reorder)

The **Monitoring Panels** page (`#panels` / `PanelsGridView`) renders condition-oriented cards containing biomarker and index chips with color-coded status dots.

Currently, marker chips always display the friendly name (`test.friendlyName`), all declared markers in each panel are shown regardless of whether they have been tested or what their latest status is, and panels are presented in a fixed static order without the ability to hide irrelevant panels or create new ones.

This task adds rich display controls and panel management to the Monitoring Panels view:
1. **Compact view toggle** (implemented; replaces the planned `Short Name` / `Friendly Name` toggle).
2. **Status Filter toggles** (implemented): Multi-state toggles for `Not Tested` (grey), `In Range` (green), `Unknown / Borderline` (yellow), and `Out of Range` (red).
3. **Edit Panels view**:
   - **Hide / Show panels**: Toggle visibility for individual panels to reduce clutter.
   - **Create custom panels**: Define new panels with chosen markers, icon, color, and description.
   - **Reorder panels by dragging**: Drag-and-drop repositioning of panel cards in the grid.

## 1. Compact View

> **Implemented (2026-09-11).** A "Compact view" switch (`SwitchToggle`, `web/src/components/primitives/SwitchToggle.tsx`, `aria-pressed`) sits at the right of the Monitoring Panels toolbar, beside the search box. It replaces the Short Name / Friendly Name toggle this section used to plan.

- **Off (default)**: observation chips show `test.friendlyName` and index chips `def.friendlyName`; each card keeps its "Observations" and "Indices" labels and its "View panel →" link.
- **On**: observation chips show the catalog short name `test.shortName` and index chips `def.shortName`; the "Observations" and "Indices" labels and the "View panel →" link are hidden (the card header still opens the panel), and the thin divider between the two chip groups stays. Cards also get narrower, not just shorter: `.mc-panels-grid--compact` (`web/src/styles/index.css`) sets a 200px column minimum with a smaller icon disc, title and chips, chosen by measuring. At a 1280px window the normal grid is 3 columns with a median card width/height ratio of 0.406, and the compact grid is 4 columns at 0.436 (+7%). At 1024px it is 0.518 across 2 columns against 0.496 across 3.
- **Marker count**: "N markers", or "N of M markers" while a status filter is on, sits in the card's top-right corner (`.mc-panel-count`) in both views, above the title line, so it never takes width from a long panel name.
- **Persistence**: unlike the status filter, this is a view preference. It is stored as `compactPanels` in `bloodtests_view_settings_v1`, beside the unit system and sample limit. `loadViewSettings` / `saveViewSettings` in `ui.ts` read a missing or non-`true` value as `false`, the shell (`MedicalConditionsPage.tsx`) owns the state, and the setting goes through Clear all data and the backup's `settings.json` along with the other view settings. Tested in `web/test/ui-helpers.test.ts` and `web/test/backup-restore.test.ts`.

## 2. Status Filter Toggles (`Not Tested`, `Green`, `Yellow`, `Red`)

> **Implemented (2026-09-11).** The toolbar's former status legend (`StatusLegend`, removed) is now `StatusFilterBar.tsx` (`web/src/components/conditions/`): four `StatusToggle` pills (`web/src/components/primitives/StatusToggle.tsx` — status dot, label, count badge, `aria-pressed`) in the order In range, Borderline, Out of range, Not tested, all on by default, plus "All" and "Abnormal only" text presets. A count is the number of chips — observations and indices — in that status across the panels the search leaves visible, so a marker shown in two panels counts twice. Unchecked statuses hide their chips in every card; the card's top-right count reads "N of M markers" (observations) while any status is off, an Indices section with no visible chip is dropped, and a card left with no visible chips stays in the grid with a muted "No markers match" line. The filter composes with the search and is `useState` in `PanelsGridView.tsx`, never persisted. Pure logic (`countTones`, `toggleTone`, `filterByTone`, `isToneFilterActive`, `markerCountLabel`, the presets) is `web/src/components/conditions/statusFilter.ts`, tested by `web/test/status-filter.test.ts` across every combination of enabled statuses.

Allow users to focus on specific clinical outcomes across panels by toggling statuses on/off:

Dot colors are the status tokens (`COLOR.statusNone` / `statusOk` / `statusWarn` / `statusBad`, via `TONE_DOT` in `primitives/tones.ts`), never literals.

| Status Key | Visual Indicator | Status Meaning | Latest Result Condition |
| --- | --- | --- | --- |
| **Not Tested** | `statusNone` dot | No measurements recorded | No results found across all uploaded reports |
| **In Range** | `statusOk` dot | Normal / within range | Latest result within reference limits (`in-range` / `ok`) |
| **Unknown** | `statusWarn` dot | Borderline / no reference range | Reported without reference range or intermediate zone (`unknown` / `warn`) |
| **Out of Range**| `statusBad` dot | Flagged abnormal | Latest result outside reference limits (`out-of-range` / `bad`) |

### Interaction Model:
- **Multi-select toggles**: Users can enable/disable any combination:
  - *Example 1*: Enable only `Red` + `Yellow` to immediately highlight all abnormal and borderline markers across all panels.
  - *Example 2*: Toggle off `Not Tested` to see only markers with actual historical data.
- **Count badges**: Each toggle displays the total count of markers currently matching that status across all loaded reports.
- **Quick presets**:
  - "All" (activates all 4 statuses).
  - "Abnormal only" (activates Red + Yellow).
- **Filtering effect**:
  - Within each panel card, chips matching unchecked statuses are filtered out.
  - Marker count badge in panel header reflects visible / total (e.g. `2 of 8 markers`).
  - If a panel card has no markers matching the active filter, display a subtle empty indicator or allow hiding empty cards.

## 3. Allow to Edit Panels View (`Edit Panels Mode`)

Add an **Edit Panels** button to the toolbar to customize the panel grid:

### 3.1 Hide / Show Panels
- In edit mode, each panel card displays a visibility toggle (e.g. Eye icon `👁 Visible` / `🚫 Hidden` or checkbox).
- Alternatively, provide an "Organize Panels" drawer/modal listing all panels with checkboxes to show/hide.
- Hidden panels are removed from the default grid and sidebar navigation, letting users focus only on panels relevant to their health monitoring.
- A "Hidden Panels" counter / drawer allows unhiding any panel at any time.

### 3.2 Create Custom Panels
- **"+ New Panel"** button in edit mode or toolbar.
- Builder modal / interface:
  - **Panel Name & Category**: e.g., "Longevity Protocol", "Cardiovascular Deep-Dive".
  - **Icon & Accent Color**: Visual icon selector and theme color.
  - **Description**: Target condition or clinical rationale.
  - **Marker Picker**: Search and select any analyte from the catalog (by LOINC, friendly name, or short name) or computed index.
- Custom panels appear alongside standard panels in the grid with an edit/delete option.
- Stored locally in browser storage and round-tripped through backup JSON/zip export.

### 3.3 Reorder Panels by Dragging (Drag-and-Drop)
- In edit mode, panel cards become draggable with a visible grab handle (`GripVertical`) and hover/active states.
- Reordering panels updates the grid layout in real time.
- The custom sort order (`panelOrder: string[]`) is persisted in `localStorage`.
- Provide accessible keyboard reorder controls (Move Earlier / Move Later) as a fallback.
- "Reset Order" action to restore standard clinical grouping.
