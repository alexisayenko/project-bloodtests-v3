# Rename the Analysis tab to Results and add a Trends tab

Two changes to the in-page tab strip (`TabBar`):

1. Rename **Analysis** to **Results**.
2. Insert a new tab, **Trends**, directly after it.

## What the code says

- `TabBar` is rendered by both `PanelDetailView` (`DETAIL_TABS`:
  Analysis, What's in range, Charts) and `AllObservationsView`
  (`OBSERVATIONS_TABS`: Analysis, What's in range). Both are
  affected, and the tab lists are two separate constants — keeping
  them consistent is manual.
- The tab id is **not** in the URL. `routing.ts` routes only the five
  top-level sections plus panel/report detail; the active tab is
  component state. So the rename is a label change with no
  link-compatibility cost — the `'analysis'` id can stay or change
  freely.
- "Analysis tab" is prose in `CLAUDE.md` and in eight files under
  `docs/` (`milestones.md`, `ui-ux/journeys.md`,
  `ui-ux/style-guide.md`, three `product/concepts/` files,
  `tech/decisions/adr-0005-…`, `tasks/task-0010.md`). The rename
  carries a doc sweep. `ControlsBar`'s own comment and the
  `AnalysisSettings` / `ANALYSIS_SETTINGS_KEY` naming also derive
  from the old label — decide whether those follow (a storage-key
  change is a migration, not a rename).

## Outcome

Shipped 2026-09-09, as a label change only.

- **Results** replaces **Analysis** in both tab strips, and **Trends**
  sits directly after it in both — Panel Detail now reads Results ·
  Trends · What's in range · Charts, All Observations Results · Trends
  · What's in range.
- **Trends ships deliberately empty**: `TrendsView.tsx` renders one
  muted line, "Nothing here yet — this tab is a placeholder." What it
  eventually contains is still open — the open question below stands,
  and nothing here commits to an answer.
- **The internals deliberately keep the old name.** `AnalysisSettings`,
  `ANALYSIS_SETTINGS_KEY` (a storage-key change would be a migration,
  not a rename), `ControlsBar`'s comment and the `'analysis'` tab id
  are all unchanged. The label and the type name now diverge on
  purpose.
- `DETAIL_TABS` and `OBSERVATIONS_TABS` stay two constants: the lists
  genuinely differ (Charts is Panel Detail only), and each is four
  lines in the file that renders it.

## Open questions — settled at the time, or still open

- **What is in Trends? — still open.** The tab shipped empty rather
  than guessing. It is the first thing to decide, because the neighbours already occupy the obvious ground:
  "What's in range" is a normalized-overlay **time chart** of every
  marker and index, and Panel Detail's "Charts" is the 3D stacked
  time view. A third trend-shaped tab needs a distinction the user
  can state in one sentence, or it becomes a duplicate of one of
  them. Plausible framings worth choosing between: per-marker
  direction and rate of change as a table (up/down/flat since last
  draw, slope over the window), rather than another chart; or a
  consolidation that absorbs one of the existing two.
- ~~**Does Trends appear in both views or only one?**~~ Settled: both.
  "What's in range"
  is in both, "Charts" only in Panel Detail. Whichever Trends turns
  out to be may not be meaningful for the full unfiltered
  All Observations set — if so, drop it from one strip then.
- **Load cost.** "What's in range" and "Charts" are both
  `React.lazy` behind `<Suspense>` so their chart engines stay off
  the entry bundle. Anything chart-shaped in Trends must follow that
  pattern.
