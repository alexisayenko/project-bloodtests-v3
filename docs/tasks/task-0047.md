# Add golden tests for cFT formulas cross-checked against issam.ch

Alex wants golden-master tests that cross-check the app's calculated
free-testosterone (cFT) formulas against an independent, trusted
reference implementation — specifically
<https://www.issam.ch/freetesto.htm> (ISSAM's Free & Bioavailable
Testosterone calculator, Hormonology department, University Hospital
of Ghent), which Alex named as a "validated" calculator. This is
already the subject of `docs/tasks/task-0045.md` (adding issam.ch as
a cited reference on `cft`'s `references` array) — read that file
too; this task is about testing against it, not citing it.

In scope: `cft` (Vermeulen), `cftlh` (Ly & Handelsman), and later
Nanjee-Wheeler if/when task-0046 is built.

## What the code says

`web/test/computed-indices.test.ts` already has golden-master
`describe` blocks for `cft` (`'calculatedFreeTestosterone via the cft
index (Vermeulen golden master)'`) and `cftlh`
(`'cftlh (calculated free testosterone, Ly & Handelsman 2005)'`).
Each pulls the `IndexDef` by key from `INDEX_DEFS`, calls `.fn(...)`
with fixed T/SHBG(/ALB) inputs, and asserts the numeric result with
`toBeCloseTo(expected, precision)` — expected values ported from v2
or hand-computed, not sourced from an external calculator. This task
adds a new layer of golden values whose expected numbers come from
running issam.ch's calculator directly, alongside (not replacing) the
existing internally-derived fixtures.

## Proposal

issam.ch is a live web page, not an API — there's no way to call it
programmatically from a test suite. The practical approach:

1. A human runs a handful of representative T / SHBG / (albumin)
   combinations through the live issam.ch calculator by hand.
2. Record each input triple and the calculator's output as a fixed
   expected value in a new test block in `computed-indices.test.ts`
   (or a new file alongside it), with a comment citing the URL and
   the date the cross-check was performed — the same
   `retrieved: 'YYYY-MM-DD'` discipline `indexDefs.ts`'s `references`
   entries already use, so the fixture's provenance is traceable and
   its staleness is visible if issam.ch ever changes its constants.
3. Assert `cft.fn(...)` against those recorded values with a
   reasonable tolerance (issam.ch likely rounds displayed output, so
   an exact `toBeCloseTo(expected, 5)` may be too strict — probably
   1–2 decimal places, to be decided once real output is in hand).

**This cannot be done from a static task doc.** Recording the
expected values requires a human to actually open issam.ch, enter
each input combination, and transcribe what it displays — no live
comparison is possible without that step. Flagging this explicitly:
whoever picks up this task needs to run the calculator by hand first.

## Can cftlh be cross-checked the same way?

Per `task-0045.md`'s own research (already done, not redone here):
issam.ch's page text does not name "Vermeulen" or cite the 1999 paper
directly, but its calculator is understood to implement the standard
Vermeulen competitive-binding model — task-0045 describes it as
"Vermeulen-only as far as could be confirmed" and explicitly
recommends citing issam.ch on `cft` alone, "unless someone verifies it
also offers the Ly & Handelsman regression." No evidence issam.ch
exposes a formula selector or offers Ly & Handelsman as an option, so
`cftlh` likely **cannot** be cross-checked against issam.ch — it would
need a different validated reference (not identified here) or stay
untested against an external source for now.
