# Implement FIB-4 for fibrosis-risk staging

Goal: a new computed index, FIB-4, on the Fatty Liver panel alongside
De Ritis.

## Why now

The De Ritis ratio's `meaning`/`consensus` prose in
`web/src/data/indexDefs.ts` (`key: 'deritis'`) was just corrected to
say plainly that it characterizes the *pattern* of liver injury
(viral vs alcoholic vs muscle source), not a validated standalone
fatty-liver assessment — it is not a steatosis or fibrosis staging
tool. That leaves the Fatty Liver panel with no guideline-supported
fibrosis-risk stratification at all. FIB-4 (age, AST, ALT, platelet
count) is the tool AASLD guidance actually points to for this — see
["Spare Me the Jab? Noninvasive Assessment in Patients With
MASLD"](https://www.aasld.org/liver-fellow-network/core-series/clinical-pearls/spare-me-jab-noninvasive-assessment-patients-masld).
It is not implemented anywhere in this app today.

This also closes a gap the engine has been carrying since the v2
port: `computedIndices.ts`'s header comment already names FIB-4
explicitly —

> Age/sex-dependent indices (eGFR x3, FIB-4) are intentionally NOT
> ported; eGFR stays the lab-reported LOINC value it already was.

— and `docs/product/concepts/computed-index.md` records the same
reason: "v3 had nothing to source age or sex from when they were
ported. Database details has since gained `sex` and `birthYear`, so
that reason no longer holds ([task-0004](task-0004.md)
tracks using them)." task-0004 (use sex/birthYear for reference
ranges) is still `to do`. FIB-4 is the second consumer of the same
missing capability — sourcing a patient attribute rather than a
marker value as an index input.

## Formula and inputs

`FIB-4 = (Age × AST) / (Platelets × √ALT)`

Inputs: age, AST, ALT, platelet count. AST/ALT/platelets are
ordinary marker inputs the way every other index sources them
(`MARKER_LOINC` / `MARKER_CANDIDATE_LOINCS` in `computedIndices.ts`).
Age is not — no existing index takes a non-marker input, so `needs` /
`Markers` (`Record<string, number | undefined>`, keyed by marker
short name and populated from `resultsByLoinc`) has never had to
represent anything but a lab value on the draw's date.

## Open design question — do not resolve in passing

Where does "age" come from for a given draw?

- The envelope's `birthYear` (Database details metadata,
  `bloodtests_envelope_meta_v1`) combined with the draw's own date
  is the only candidate source today — there is no lab-reported age
  marker. That makes age a *report-level* or *subject-level* input,
  not a per-observation one, which is a new shape for this engine:
  every existing index input is looked up by LOINC in
  `resultsByLoinc` for that one draw.
- `birthYear` alone gives a year, not a birth date — age at a given
  draw is therefore approximate (±1 year) unless a more precise DOB
  is captured. Whether that precision matters for FIB-4's cutoffs is
  worth checking against the source guidance before deciding it's
  good enough.
- `birthYear` is optional metadata a user may not have filled in.
  FIB-4 needs a documented behavior for that case — most likely: no
  age, no FIB-4 for that draw, same as any other missing input
  (`fn` returns `null`) — but that's a call for whoever designs the
  plumbing, not assumed here.
- How age reaches `markersForIndex`/`computeIndex` (both currently
  take only `resultsByLoinc`) needs a design decision: a new
  parameter threaded through, a synthetic pseudo-marker, or
  something else. Don't resolve this in the ticket — flag it for
  implementation.

This ticket deliberately stops at flagging the question. task-0004
may end up resolving the sourcing mechanism for reference ranges
first, in which case FIB-4 should reuse whatever it builds rather
than inventing a second age/DOB pathway.

## Cutoffs — verify before implementing

Commonly cited FIB-4 cutoffs: <1.30 (low probability of advanced
fibrosis), 1.30–2.67 (indeterminate), >2.67 (high probability). These
are given here as a starting point only, transcribed from memory of
general FIB-4 literature, not from the AASLD page cited above or any
other primary source read for this ticket — they must be checked
against a primary source (the AASLD clinical pearl, or the original
FIB-4 validation/guideline papers) before shipping, the same way
task-0012's Martin-Hopkins factor table was verified cell-by-cell
before being trusted. Some guidance also age-bands the high-risk
cutoff (e.g. a lower threshold under 65); check for that too rather
than assuming one flat cut-point set.

## Evidence tier

Give FIB-4 `evidenceLevel: 'guideline'` only once it ships with a
verified primary-source citation (matching the pattern of `tsat` and
other `guideline`-tier indices in `indexDefs.ts`, which cite the
specific society guideline the threshold comes from) — not as a
foregone conclusion of this ticket. If the verified cutoffs turn out
to be consensus-based rather than a formal guideline recommendation,
tier it `consensus` instead, the way `deritis` itself is tiered.

## Panel and LOINC

Panel: Fatty Liver (`web/public/data/monitoring-panels.json`,
`"name": "Fatty Liver"`), alongside `deritis`. Check whether FIB-4
has a LOINC of its own the way Martin-Hopkins LDL-C does
(task-0012) before deciding whether the index def carries one.
