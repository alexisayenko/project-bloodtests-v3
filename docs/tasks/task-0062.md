# Add cholesterol/triglyceride molecule icons and a holder-plus-cargo diagram to Lipid Transport

Alex designed two new icons — a cholesterol molecule (reusing the three-ring
steroid motif already embedded in `CarrierIcon`, redrawn outline-only) and a
triglyceride molecule (glycerol backbone with three fatty-acid tails), both
sketched and approved in chat — and asked for two things on Lipid Transport
(`#lipids`, [task-0060](task-0060.md)):

1. A new diagram showing a lipoprotein's structural apolipoprotein connected
   to its two docked cargo chips, mirroring the holder-plus-cargo visual
   language Hormonal Pathways already uses for SHBG holding testosterone
   (`Carrier`, `HormonalPathwaysView.tsx`: a node, a bond, a node).
2. Swapping the flat-colored TRIG/Chol blob regions in the particle-row
   glyphs (`LipidParticleGlyph.tsx`, Data mode) for the new icon shapes,
   still sized off the sourced composition shares.

## New icons

`web/src/components/conditions/customIcons.tsx`, appended under a "Lipid
molecule icons" comment block, both following the file's existing
`IconComponent` shape (`size`/`color`/`strokeWidth` props, `viewBox="0 0 48
48"`):

- **`CholesterolIcon`** — exactly `CarrierIcon`'s three-ring steroid cargo
  path, redrawn as its own icon: outline only (`fill="none"`, `stroke=
  {color}`), no fill, default color `#94a028` (the bile-green Alex specified),
  `strokeWidth` 1.4, `strokeLinejoin="round"`.
- **`TriglycerideIcon`** — a new glyph: glycerol backbone trimmed to its
  three attachment points plus three fatty-acid tails (2x length, per Alex's
  approved sketch), default color `#f9d77a` (matching the app's existing
  `--lipid-trig` token), `strokeWidth` 2, round caps/joins, three small
  filled circles at the backbone's attachment points.

Both take `x`/`y` via their existing `SVGProps<SVGSVGElement>` passthrough
(`{...rest}`), which is what lets them be nested and positioned as ordinary
child `<svg>` elements inside another SVG — used by both call sites below.

## 1. The cargo diagram

`LipidTransportView.tsx`'s new `CargoDiagram` component, rendered once,
directly under the page's `ArtworkNote`, before the particle grid.

**Scoping decision**: one representative particle, not all six. LDL was
picked — a single apoprotein (ApoB-100, no linked second protein the way
Lp(a) has apo(a)), and the most clinically familiar of the six ("bad
cholesterol"), so it reads clearly as the example the caption calls out
rather than needing per-particle disambiguation. The diagram is a static,
non-interactive illustration of the *pattern*, not a live readout for a
specific particle — extending it to all six would duplicate the particle row
below it (which already shows every particle's own apoprotein pill and cargo
chips) rather than adding anything.

Built from the same pieces `Carrier` (`HormonalPathwaysView.tsx`) uses —
`.mc-pathway-anchor`, `.mc-pathway-bond`, `.mc-pathway-bubble`,
`.mc-pathway-caption`, `.mc-pathway-node-label` — with no new CSS: `CarrierIcon`
in the center (sized the same way `HormonalPathwaysView`'s `CARRIER_SIZE`
is, since its drawing likewise spans ~42.6 of its 48-unit viewBox), a bond
on each side to a docked bubble holding `TriglycerideIcon` / `CholesterolIcon`
at molecular-actor size (`SIZE.molecular`, `pathwayShared.ts`). Deliberately
not wired into `LipidAssociations` or the badge/chip system — it is a fixed
explanatory picture, not a live measurement node.

No new CSS classes were added to `web/src/styles/index.css` at all — another
session was concurrently editing that file (a sidebar-toggle restyle), so
the diagram's own layout (row spacing, caption margins, section title) is
done with inline `style` props instead, per the session's own instruction to
avoid shared-file contention where a reasonable inline alternative exists.

## 2. Particle-glyph icon swap

`LipidParticleGlyph.tsx`'s `ParticleGlyph`: the TRIG/Chol regions previously
rendered as a flat-filled organic polygon (`organicRegions()`'s stacked-band
output, area proportional to the sourced share). Now each region renders as:

- a thin dashed outline of that same organic polygon (so the region's own
  extent — the thing that encodes the composition share — stays visible),
  and
- the matching icon (`TriglycerideIcon` / `CholesterolIcon`), centered on
  the region's own bounding box and sized to `min(width, height) * 0.8`
  (floored at 9px so a near-zero share still draws something), via the new
  `regionIcon()` helper.

This keeps the "scaled to fit... proportional sizing" property `organicRegions`
already provided — a bigger composition share still produces a visibly bigger
icon (LDL's ~50% cholesterol share renders a markedly larger `CholesterolIcon`
than its ~10% triglyceride share; HDL's ~5% cholesterol renders barely
visible, by design) — without inventing a second sizing model.

**Color decision**: the particle-row glyphs keep the page's existing teal
(`--lipid-chol`) / yellow (`--lipid-trig`) tokens rather than switching to
the new bile-green cholesterol treatment. Those tokens are already the
page's established palette — the same colors label the Size and composition
table below the particles and the chip dots — so changing only the glyph
icons' color would read as an inconsistency between the icon and everything
around it referencing the same quantity. The bile-green/black-outline
treatment Alex approved is used as specified on the new cargo diagram, which
is a distinct, purpose-built illustration rather than part of the existing
particle-row chrome.

## Update 2026-09-17: TRIG/Chol drawn as circle stacks, one shared bond length

## Update 2026-09-17: 3/2/1 taper for both compounds, plus chylomicron/HDL/Lp(a)

Two follow-ups from the same session.

**Chol tapers 3/2/1 too, not a fixed count.** Checking the circle counts
against a rough mass estimate (density x volume from each particle's
sourced diameter/density range) showed Chol declining by about the same
factor as the circle-count taper implies (VLDL's Chol mass estimate is
roughly 3x IDL's rough interpolation and LDL's), so `ParticleNode` now takes
a `cholCount` per stage (VLDL 3, IDL 2, LDL 1) instead of a shared constant
-- matching TRIG's own 3/2/1. These mass figures are Claude's own
density x volume extrapolation from the sourced diameter/density ranges,
not something Cox/Feingold state directly, and are wide (VLDL's diameter
range alone spans a ~19x volume difference) -- kept as a sanity check on
the illustration, not as new sourced data.

**Chylomicron, HDL and Lp(a) added, deliberately unconnected to the VLDL
chain.** These three aren't stages of VLDL's transformation (chylomicron is
made in the intestine from dietary fat, not the liver; HDL's ApoA-I is
secreted lipid-poor and acquires its cargo later from peripheral tissues,
not packaged the way VLDL is), so drawing a bond arrow from Liver/VLDL to
any of them would misrepresent the biology. Instead:

- `ParticleNode` gained a `holder` prop (the structural apolipoprotein
  label: ApoB-48 for chylomicron, ApoA-I for HDL, ApoB-100 for Lp(a) same
  as the VLDL chain) and an `extraApo` prop for Lp(a)'s second protein --
  a small docked pill (reusing `CarrierIcon` at ~55% size) with a `(a)`
  tag, positioned at the main ApoB-100 icon's corner.
- Chylomicron gets its own zone, "Intestine" (`mc-pathway-band`, same
  rotated-caption convention as Liver/Blood Transport), placed before
  Liver since dietary fat is processed first; no organ artwork, since none
  exists for the intestine yet.
- HDL and Lp(a) render as a second row inside the existing Blood Transport
  zone, below the VLDL/IDL/LDL chain, with their own dashed outlines and
  bond lines but no connecting arrow to the chain.
- `LipidAssociations`' per-particle bond/outline loop now covers all six
  particle ids (`vldl`, `idl`, `ldl`, `chylomicron`, `hdl`, `lpa`) instead
  of the endogenous three.
- Counts (illustrative, not sourced beyond the % composition table): TRIG
  4 / Chol 1 for chylomicron (90%/3% of mass, the most TRIG-dominant
  particle); TRIG 1 / Chol 1 for both HDL (5%/20%, but by far the smallest
  particle in absolute terms) and Lp(a) (no sourced composition, mirrors
  LDL's own count since it's structurally an LDL particle plus apo(a)).
