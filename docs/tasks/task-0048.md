# Add golden tests for LDL-C formulas cross-checked against MSD Manuals' calculator

Same idea as task-0047, for the three calculated LDL-C estimates:
`ldlf` (Friedewald), `ldls` (Sampson/NIH equation 2), and `ldlmh`
(Martin-Hopkins, just implemented per task-0012).

## What the code says

`web/test/computed-indices.test.ts` already carries golden-master
blocks for all three: `'LDL-C estimates (Friedewald 1972 / Sampson
NIH-2 2020)'` (covering `ldlf` and `ldls`) and `'LDL-C estimate
(Martin-Hopkins 2013)'` (covering `ldlmh`). Each pulls the `IndexDef`
by key, calls `.fn(...)` with fixed TC/HDL-C/TRIG inputs, and asserts
with `toBeCloseTo(expected, precision)` — e.g. `ldlmh.fn(m(200, 50,
150))` expected `123.684211` to 5 decimal places. These expected
values are hand-computed from the formulas/table directly (per
task-0012's implementation notes, independently re-confirmed against
the primary JAMA source and a second transcription), not sourced from
an external calculator. This task adds a further layer of golden
values whose expected numbers come from running external, independent
calculators.

## Proposal, per formula

- **Friedewald (`ldlf`)** — simple enough (`TC − HDL − TG/5`) to
  hand-verify without an external calculator. No live cross-check
  needed; the existing hand-computed fixtures already cover it
  adequately.
- **Sampson (`ldls`)** — a more involved formula
  (`TC/0.948 − HDL/0.971 − (TG/8.56 + TG×nonHDL/2140 − TG²/16100) −
  9.44`); no specific external live calculator identified here as a
  cross-check target. Leave as hand-computed unless a validated
  Sampson/NIH-equation-2 calculator is identified separately.
- **Martin-Hopkins (`ldlmh`)** — the one most worth cross-checking
  live, since it's table-driven (180-cell lookup) rather than a
  closed-form formula, so a transcription error in
  `web/public/data/martin-hopkins-ldl-table.json` wouldn't necessarily
  show up as an obviously-wrong number. MSD Manuals hosts a live
  Martin-Hopkins calculator:
  <https://www.msdmanuals.com/professional/multimedia/clinical-calculator/martin-equation-for-low-density-lipoprotein-ldl-c>
  — named by Alex directly as the calculator to cross-check against.
  `task-0012.md`'s implementation notes cite the primary JAMA source
  (Martin SS et al. 2013) and a ResearchGate figure for the table
  transcription itself, not clinicalsci.info or MSD Manuals — MSD
  Manuals is a separate, additional candidate for this cross-check
  task, not something task-0012 already cited.

## Same "needs a human" caveat as task-0047

MSD Manuals' calculator is a live web page, not an API — no
programmatic access from a test suite. The practical approach:

1. A human runs a handful of representative TC / HDL-C / TG
   combinations through the live MSD Manuals calculator by hand.
2. Record each input triple and the calculator's output as a fixed
   expected value in a new test block in `computed-indices.test.ts`,
   with a comment citing the URL and the date the cross-check was
   performed (the same `retrieved: 'YYYY-MM-DD'` provenance discipline
   used elsewhere).
3. Assert `ldlmh.fn(...)` against those recorded values with an
   appropriate tolerance (displayed output is likely rounded to
   whole mg/dL, so `toBeCloseTo(expected, 0)` or similar, to be
   decided once real output is in hand).

**This cannot be done from a static task doc** — recording the
expected values requires a human to actually open the MSD Manuals
calculator, enter each input combination, and transcribe the result.
No live comparison is possible without that step.
