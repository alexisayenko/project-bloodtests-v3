# Fix Import all data not refreshing Database details on screen after restore

Confirmed broken — not a storage bug, a stale-React-state bug. The meta
(subject/sex/birthYear/notes) *is* correctly written to `localStorage` by
Import all data; the Database details card on screen just never re-reads it
afterward, so it keeps showing the pre-import values until the page is
reloaded.

## What the code says

- **The write path is correct.** `readBackup` → `readReports`
  (`web/src/data/backupRestore.ts:51-71`) parses `lab-reports.json`'s
  envelope and calls `sanitizeEnvelopeMeta(envelope)` to produce
  `reports.meta`. `restoreReports` (line 148-153) then does
  `if (Object.keys(reports.meta).length > 0) saveEnvelopeMeta(reports.meta);`
  — unconditional on report count, so an envelope with meta but zero
  reports still restores its meta. `saveEnvelopeMeta`
  (`web/src/data/envelopeMeta.ts:36-42`) writes
  `bloodtests_envelope_meta_v1` to `localStorage`. This much genuinely
  works: a fresh page load after Import all data shows the restored
  Subject/Sex/Birth year/Notes correctly.
- **The read path that feeds the screen is a stale `useState` initializer.**
  `DatabaseDetailsCard` (`web/src/components/conditions/AccountView.tsx:152-161`):
  ```
  const [meta, setMeta] = useState<EnvelopeMeta>(() => loadEnvelopeMeta());
  ```
  This lazy initializer runs once, on mount. `DatabaseDetailsCard` lives
  inside `AccountView`, which is the same component instance the whole time
  someone is on the `#account` route — and Import all data's button is
  rendered by that same `AccountView` (`web/src/components/conditions/AccountView.tsx:465-470`,
  `importBackup` → `onImportAll`). So the click happens without
  `DatabaseDetailsCard` ever unmounting, and `meta` state is never
  re-initialized from the now-updated `localStorage`.
- **The shell's own post-restore reload misses envelope meta.**
  `MedicalConditionsPage.tsx`'s `onImportAll` (`web/src/components/conditions/MedicalConditionsPage.tsx:215-222`)
  calls `restoreBackup(...)` then `reloadStoredState()`
  (lines 202-208):
  ```
  const reloadStoredState = () => {
    reloadScheduled();
    const stored = loadViewSettings();
    setUnitSystem(stored.unitSystem);
    setSampleLimit(stored.sampleLimit);
    setCompactPanels(stored.compactPanels);
  };
  ```
  This reloads scheduled visits and the three view-settings fields the
  shell itself owns — but envelope meta is owned by `DatabaseDetailsCard`'s
  own local state, which `MedicalConditionsPage` has no handle on at all.
  There is no equivalent of `reloadScheduled()` for envelope meta anywhere
  in the import path.
- **Symptom matches exactly:** after "Import all data" completes and the
  "Backup imported." notice appears (`AccountView.tsx:420`), the Subject /
  Sex / Birth year / Notes fields directly above it on the same page keep
  showing whatever they held before the import (blank, if this was a fresh
  browser) — not the restored values — until the page is reloaded or
  `#account` is left and re-entered in a way that remounts `AccountView`.
  (Whether route-switching away from and back to `#account` remounts
  `AccountView` — and so would incidentally "fix" it — was not traced
  further here; regardless, it shouldn't be required.)

## Fix direction (not applied — documentation only per this task's scope)

The natural fix is the same shape as `reloadStoredState`: either (a) lift
envelope meta into `MedicalConditionsPage`'s own state and pass it down as
a prop, reloading it alongside scheduled/view-settings after
`restoreBackup`, or (b) keep it local to `DatabaseDetailsCard` but expose a
`key` or reload callback so `AccountView`/`MedicalConditionsPage` can force
it to re-read `localStorage` after a successful import (e.g. remount via
`key={importGeneration}`, or a `reload()` escape hatch mirroring
`useScheduled`'s own `onReload`). (a) is the more consistent fix — every
other piece of restored state already flows down from the shell rather than
self-loading — but touches more call sites.
